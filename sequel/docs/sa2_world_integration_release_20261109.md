# 裏町・遊技場・ダンジョン入口の本番統合（2026-11-09）

## 現在の仕様

裏町の西端（x≤−23.55）を左へ進むと、採用済み16m幅×10m高の遊技場がある別フロアへロードする。遊技場の東端（x≥23.55）を右へ進むと元の裏町の西側へ戻る。既存の建物の位置は動かしていない。

裏町の右に4mの入口前区画を追加し、歩行範囲を−24〜28mにした。ダンジョン入口はx=26。右直進で難易度メニューを開き、既存ダンジョンへ入る。退出先は元の裏町に戻る。従来の通常街の入口・ダンジョン進行は維持。遊技場の独立した歩行範囲は−24〜24mのまま。

公開時の確認先（vへ最新コミットを付けるとHTML再取得の目印になる）：
- 裏町：`https://yyvape-dev.github.io/SA/sequel/web/?town=back`

- 裏町のダンジョン入口前：`https://yyvape-dev.github.io/SA/sequel/web/?town=back&at=gate`

## 採用・変更したもの

- 採用元 `test/sa2-t4-gamehall-relayout-20261109` のコミット `6404831131a8f9b4bb31f7711ac2453e354f57bd`。必要な8素材と2スクリプトだけを取り込んだ。`gamehall_animation.gd` は採用元とバイト一致。フロアのコードは製品用に改名し、ダンジョン門を複製しないこと、歩道まで隠さないこと、画像欠損時に元の街を破壊しないことを調整。
- 元の裏町ではダンジョン門を生成していなかったため `_build_gate()` を呼び出し、門の現在位置で入場を判定する。退出時に無条件で通常街へ戻していた処理は、裏町から入った時だけ裏町へ戻す分岐へ変更。
- 3D側面、柱、路地壁などは既存のtex_brick/iron/plaster/boardsを使用。world triplanarで繰り返し、壁に引き伸ばした1枚絵を作らない。素材は共有し、個別の樽の暗化だけduplicateで分離する。
- 未完成だった街路酒場A/B/C/Dは、既設酒場の完成画を参照して生成した4種類の絵へ置換。元シートの実寸は1254×1254（要求2048から勝手な拡大はせず、実納品サイズを記録）。切り出し後もリサイズしていない。既存幅・位置に合わせて平面へ貼る。小さな吊り布は生成画の布片を使用。
- 大型遊技場への置き換え方針で廃止予定だった旧遊技屋台を撤去。図面用の緑の足元マーカーは通常表示から除きBT_GUIDES時だけ表示。仮の緑円柱は既存の描き込み済み緑ランタン画像へ置換。
- スマホの横長画面で外側が抜けないよう、背景の左右壁を延長。床幅の延長は裏町だけに限定し、通常街の床幅60mは維持。

画像の原寸を下げたり、採用済みの建物・人物を再生成したりしていない。新規専用シェーダーは追加せずGodot標準材質を使用。SA1・承認済み本文・T2/T3全体・テストブランチへの書込みはない。

## 読み込み・資源管理

街の画像はbt1、遊技場はgh1地区パックへ分離し、遊技場へ初めて入る時だけgh1を取得する。既存Webエンジン4.7.2をそのまま再利用しPCKを再生成する。gh1には背景・人物atlas・36フレームの採用アニメーション・必要JSONを含む。

退場時に遊技場Levelノードを解放し、背景画像キャッシュも外す。大きなアニメーションatlasの参照はLevel内のアニメーションノードに限定する。実機のピークVRAM／メモリは未計測であり、解像度を下げてPASSにしていない。

失敗時は元の街を残したまま暗転・入力ロックを解除。端から離れるまで自動再試行しない。再試行成功時にエラー表示を消す。移動中／モーダル中／ダンジョン中のフロア切替を抑止。仲間とカメラを新しいプレイヤー位置へ戻す。

## 不具合・レビュー・検証

失敗先行のGodotテストで以下を確認してから修正した。
- 初回12項目：入口なし、遊技場接続なし、側面と4屋台が仮表示、旧遊技屋台が残存。
- 材質共有：樽の暗化が共通材質を変更してしまう問題。暗化対象だけ複製。
- 実描画：遊技場のマスクが歩道まで非表示にする問題。地面はマスクしない。
- 実ダンジョン切替：解放済み前景への参照。_clear_levelでbt_fgを消去。
- 独立レビューのImportant 1件：取得失敗で暗転・毎フレーム再試行が続く。ダウンロード境界を失敗させるテストと実画像欠損テストで再現し、街への操作復帰と正常な再試行まで検証。
- レビューのMinor 2件：床材質の強参照増加は同じレベル寿命管理の問題として小さく修正し、反復構築して件数が増えないテストを追加。パック分離は実PCKを読むverify_world_packs.pyで検証する。

最終試験：施設テスト06/08・11/15、世界統合、取得／画像欠損からの復帰。テスト実行の終了コードだけでなくSCRIPT ERROR/ERRORが無いことも確認する。既存ダンジョンBOTはnormal3周・hard1周の全4周を実際にクリアし、敵AIによる被弾と出口ロックも確認。

実レンダリング動画は、裏町→左の遊技場→元の裏町→右の入口→タッチ注入による難易度選択→ダンジョンを連続撮影。短縮のため動画中の退出は既存close_result APIを呼ぶ。この短い映像だけでダンジョンクリアしたとは主張せず、実クリア試験と分ける。

## 再現・外部AIへの引き継ぎ

- 画像由来：`art/painted_bt_src/world_finish_provenance_20261109.json`。
- 生成画の再切り出し：`python3 sequel/tools/prepare_world_art.py`（Pillow/numpy/scipy）。生成自体は非決定的、保存済み原画からの切り出しは決定的。
- ネイティブ試験：`Godot --headless --path sequel --fixed-fps 60 --script res://tests/sa2_world_integration_test.gd` と `sa2_world_failure_test.gd`、既存施設テスト2本。
- 実ダンジョン試験：`DUNGEON_TEST=1 Godot --headless --path sequel --fixed-fps 60`。
- Web生成：`GODOT_BIN=/path/to/Godot WEB_PACK_ONLY=1 WEB_OUT=/absolute/preview python3 -I sequel/tools/export_web.py`。
- Webパック検証：`python3 sequel/tools/verify_world_packs.py /absolute/preview`。実PCKの画像配置・未収録・本体/街/遊技場間の画像重複・元画像の二重収録を検査する。
- 実行証拠：`/workspace/sa2-world-finish-evidence/`。最終MP4は`world_integration.mp4`。最初の不合格動画ログはcapture-first-failed.log。最終のcapture.logとは区別する。
