# T6 ラナのジャストガードと既存VFX監査（2026-11-11）

## 今回の実装

- ラナの既存回避ボタン／Kは、通常移動中に敵の当たりまで0.15～0.32秒で押すとジャストガード。それ以外は既存の0.24秒・4m回避を維持する。攻撃中の回避キャンセルも既存どおり。
- ガード対象は敵の実際の攻撃向き、`atk.reach`、`atk.lane`で判定。片側攻撃の背後・範囲外は成功しない。両側大振りは背後も対象。
- 成功時は対象の攻撃を完了扱いにし、赤い床予兆を削除、0.8秒ひるみと小さな押し戻し、0.6秒被弾無効。自動反撃ダメージは付けず、その後の手動反撃を可能にする。
- 共有処理で70msのヒットストップ、小さな揺れ、接触点の金色リング＋火花を出す。既存Kenney素材を再利用。新しい画像・シェーダー・音声は作成していない。
- リリィは従来の入力条件・0.15～0.32秒のタイミングを維持し、成功時の予兆削除と同じ防御フィードバックだけ共有する。AI、通常攻撃速度、スキル、必殺技の内容は変更していない。

## 防御VFXの時間構成

| 区間 | 時間 | 処理 |
|---|---:|---|
| 予兆 | 成功入力前 | 敵の赤い床予兆 |
| 発生 | 0～45ms | 小さな光芯・金の接触輪が立ち上がる。床予兆を消す |
| 接触ピーク | 約45～100ms | 金の輪と8粒の火花、70ms停止と短い揺れ |
| 余韻 | 約100～280ms | 既存侵食と粒子減速で消える |
| 反撃猶予 | 停止後～約0.8秒 | 敵がひるむ。攻撃は手動入力 |

## 判断した点と未完了の点

- 防御の金色接触輪は、攻撃時の青／銀の軌跡と区別できる。今回の修正は、防御成立の手応えと「中断済みなのに赤い予兆が残る」不一致に限定した。
- ラナの通常攻撃は見た目の弧より当たりが少し広い。Aはr=2.8m対弧2.64m、Bは2.6m対2.18m、C最終は3.0m対2.99m。これは猶予として扱い、今回いきなり狭めて操作感を変えていない。画像の剣先と弧の最大到達点を同一視した厳密な全コマ測定まではしていない。
- ラナAの青い弧／リリィ通常の白い接触光は強いが、リリィのピークでは敵の上半身を光が覆う。爽快感を保ちながら、白芯の量と拳・脚の軌道が隠れないかを次の実機調整対象にする。「全技が完成した商用品質」とは判定していない。
- リリィの天雷は単体狙いの仕様に対して光柱・床輪は広い。複数体への範囲技と誤認しないかは次のUX監査対象。今回ダメージ範囲を広げていない。
- リリィの従来ガード候補は距離1.8m／奥行き0.9mの独立判定で、ラナのような敵の向き・実当たり形状との照合はしていない。この既存挙動は今回変更していない。
- iPhone Safariの今回変更後の操作感・フレーム時間・発光の受入は未検証。音声制作はユーザーの指定どおり次の会話へ保留。

## 検証

全17本の`*_test.gd`は終了コード0、スクリプトエラーなし。追加防御テストは時間境界、早すぎ／遅すぎ、実到達距離・奥行き、向き、大振り、既存ロック、二重被弾防止、通常回避へのフォールバック、予兆削除・効果の生成、リリィ回帰を確認した。期限切れ予兆へのガードも追加確認した。2D金色版と3Dフォールバック版は実描画のキャプチャとログで正常終了を確認した。

参照した公式資料: https://docs.godotengine.org/en/stable/classes/class_cpuparticles2d.html 。今回新しいGodot APIやシェーダーを導入せず、既存のCPU粒子・テクスチャ合成ヘルパーを再利用した。
