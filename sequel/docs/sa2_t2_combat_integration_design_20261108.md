# SA2 T2 — 既存 sequel 戦闘への接続設計（ネタバレなし／2026-11-08）

> 状態：**A案（独立したリリィ手動操作＋回避兼用ジャストガード）はユーザー承認済み。Godot 4.7.2でC1-06の自動操作・連続動画までPASS、ただし視覚・スマホ実機レビュー待ち。** 計画正本はストーリーブランチv4.2。

## 確認済み（GitHub main）
- `sequel/project.godot` はGodot 4.7.2をコメントで指定、`config/features` は4.7。新規T2ブランチは最新 `main` 起点。Godot 4.7.2公式安定版（2026-08-18）：https://godotengine.org/download/archive/4.7.2-stable/ 
- `scripts/main.gd` は `Battle`、`Player`、`Ally`、`TouchUI`、`DungeonRun`、`DungeonHud` を生成し、`enter_dungeon`／`leave_dungeon` で既存のダンジョン／街復帰を処理する。
- `scripts/player.gd` は**ラナの操作**を実装。移動・攻撃・回避・3スキル・必殺を持つ。`scripts/ally.gd` はリリィの**自動追従・自動攻撃・スキル**を実装し、直接のプレイヤー入力には未対応。
- `scripts/battle.gd` は `player_attack`／`ally_attack`／`_attack_from`、敵・味方のHP・敵生成・演出を担当。`scripts/touch_ui.gd` はラナの `attack_press`／`dodge`／`use_skill` に入力を結線している。
- `scripts/dungeon.gd` は通常／高難度の敵討伐・ボス・報酬・結果を持つ。本来のダンジョンには演習専用の非致死訓練2体・リリィ主操作・会話からの復帰条件は存在しなかった。T2専用シーンでこれらの最小試作を追加した。
- T1.5の `SA2FlowState`／会話ローダー／Controlパネル／試験用C1-06・C2-09 JSONを**新ブランチの `sequel/` に原本のまま移入**。Godot 4.7.2のCI https://github.com/yyvape-dev/SA/actions/runs/42487770597 でインポート、T1 37項目、T1.5会話テストPASS。これは表示・状態契約の検証であり、戦闘への接続・動画・スマホ試験の完了ではない。

## C1-06 仕様との差分（制作者用の物語詳細は非掲載）
- C1-06は「**リリィが操作キャラ**」「移動・通常攻撃・回避・防御」「模擬標的2体」「専用演習エリア」「結果→会話／探索へ復帰」と規定されている。
- 既存 `sequel/` の `player.gd` はラナ専用、リリィの `ally.gd` はAI制御。T2専用アダプタにより、演習中だけ手動操作が可能になった。
- `player.gd` と `touch_ui.gd` には回避入力がある一方、独立した **guard** 入力・ジャストガード処理は確認できていない。SA1 JS `battle/jguard.js` は回避とタイミング兼用の参考仕様。T2専用アダプタで同一入力方式を試作し、CI自動操作でタイミング成功を検証した。
- `sequel/` の成長セーブ `user://sa2_save.json` とT1.5フローセーブは別契約。主ストーリーの保存・復帰は追加検証が必要。

## 次の実装方式比較（設計変更の合意ゲート）

| 案 | Pros | Cons／後戻り・リスク |
|---|---|---|
| A **リリィ専用の手動操作アダプタを新設、元のAlly AIを保持**（推奨） | ラナ／既存スキル・敵処理の改変を小さくできる。演習シーンを隔離しやすい | 攻撃主体・敵の標的・HP・カメラとタッチUIの参照差替えは必要。共通戦闘APIの接合を実機テストすべき |
| B `ally.gd` に通常AI／手動操作の切替を追加 | データ・モーションの重複が少ない | 通常の仲間AI動作への回帰リスクが高い。敵の標的・UI・ゲーム進行も連動変更が必要 |
| C ラナを操作したままリリィを自動参加させる | 最短の試作 | **C1-06「リリィ操作」に不一致。正式なT2完成とは扱えないため不採用** |

**採用方式（ユーザー明示合意済み）**：A案。既存リリィの画像・攻撃・スキル・エフェクトを再利用し、演習専用の入力アダプタを分離。防御は最初SA1同様に「回避入力でタイミング成功時ジャストガード」として検証し、別ボタン追加は避ける。操作・視認性の品質が悪ければ独立防御ボタンを改めて比較／合意する。

## 実装範囲と品質ゲート
- **既存 `sequel/scripts/main.gd`・`battle.gd`・`touch_ui.gd` は変更していない。** 新しい演習プレイアブルシーンは `main.gd` を継承し、演習中のみ対象actorと敵ターゲットの参照先をリリィに差替える。通常時のラナ戦闘・仲間AI・成長／ダンジョンを保持する。`ally.gd` は演習側で敵被弾関数を互換呼出するため、省略可能な `_dead` 引数のみ追加。

- **検証済み**：Godot 4.7.2 Actions [#42490313221](https://github.com/yyvape-dev/SA/actions/runs/42490313221)、`b3879c8943ab9c7a79c1951a005663296d391f61`。T1 37項目／T1.5会話／T2防御境界テスト、シーン起動、Godot Movie Makerによる13.458秒の連続MP4で、実敵攻撃による敗北→再試行→リリィの移動・攻撃・回避・ジャストガード→模擬標的2体のHP停止→勝利→探索復帰がPASS。動画はartifact `sa2-t2-compatibility-logs` ID `13620643345`。勝敗は実HP・敵AI・当たり判定を使用。
