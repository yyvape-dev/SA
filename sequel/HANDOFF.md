## 絵の方式（決定。ユーザー承認）：下絵を塗ってもらい、箱に投影する
- AIに「前景だけ」「層ごと」を描き分けさせない（GPTの試作で失敗）。代わりに：
  1. Godot で街を箱（グレーボックス）で組む。部品（piece）＝1件の絵。
  2. `CAPTURE_GUIDE=1` で起動すると、部品ごとに「ゲームと同じ位置のカメラで、その部品だけ、背景マゼンタ」の下絵と、そのカメラの行列（`art/guide/guide.json`）を書き出す。全体の `key_full.png` は画風を決める1枚。
  3. GPT に下絵を添付して「形を変えずに上から塗る」（発注票：https://claude.ai/artifact/PUQA2u7Xmp5NVWiXQaBvzD 、生成は `tools/make_order.py`）。
  4. `python3 -I sequel/tools/import_paint.py <絵> <id>`：大きさをそろえ、形のずれを探して直し、IoU を出す（0.93未満は作り直し）。`art/painted/<id>.png` へ。
  5. ゲームは、絵があれば `proj_paint.gdshader` で下絵のカメラから箱へ投影する（マットペイント方式）。無ければ箱の仮の色。カメラが左右に動くと奥行きどおりに視差が出る。
- 事実：投影のずれは、試しの縞模様で確認済み（箱の辺と一致）。カメラが部品の中心から離れると、箱の側面の絵が伸びる（仮説：画面の端の範囲なら目立たない。実際の絵で確認する）。
- 地面はコード（前作の教訓）＋継ぎ目の無い素材の繰り返し。部品の箱や位置を変えたら、下絵を撮り直し、その部品は塗り直しになる。

- 群れ：3体〜（2群ごとに+1、最大7）。3体に1体は反対側から来る。倒しきると1.5秒後に次。敵の体力 60+10×群れの番号（前作の22+5n は2振りで倒れて連携が見えなかったので硬くした）。
- ラナの攻撃：前作の時間表（ATC・ATB、攻撃速度1.75倍）と当たりの瞬間をそのまま移植。A＝前への斬り下ろし→背への払い、B＝前への横薙ぎ→背→頭上からの払い（強い当たり）。押し続けると A→B→A と連携（各技の最後の当たりの少し後で次へ）。回避中に押した攻撃は回避のあとに出る。回避は攻撃の途中でも出せる。
- 当たりの範囲（m）：前へ 2.5〜3.2、背へも同程度、奥行き ±0.95〜1.1。敵の攻撃：左右 1.45・奥行き ±0.45 → 奥行きをずらせば避けられる（アラド型）。
- ヒットストップ：0.045秒＋当たった数×0.006（強い当たり +0.03）。被弾 0.06秒。止めている間はラナと敵だけが止まり、エフェクトは動く。
- エフェクト（コードのみ、`fx_add.gdshader`＝加算、`fx_dark.gdshader`＝下に敷く暗い層）：斬撃の帯（縦の弧／床と平行な横の弧を32°起こす）、当たりの光・切り口・火花、撃破の金の光と床の輪、ダメージの数字（白／強い当たり＝金／被弾＝赤）、敵の攻撃の床の予兆（赤い枠が当たりの瞬間まで満ちる）。
- ラナの被弾：前作の被弾4コマ（`rana.json` の `dmg`）。体力0で倒れ、1.6秒後に全快で起き上がる（今は負けの画面は無い）。左上に体力の帯（青）。

## 確認の手順
- Windows／xvfb の無い環境では `xvfb-run …` を外す。
- 撮影：`cd sequel && CAPTURE_PLAY=1 LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a -s '-screen 0 1280x720x24' godot --path . --rendering-driver opengl3 --windowed --resolution 1280x720 --fixed-fps 60` → `captures/play_NNN.png`（3コマに1枚、360コマ。前半＝ラナの連携、170コマ目から敵2体がラナを攻撃、300コマ目で回避。git 管理外）。スクリプトの誤りがあると終わらないので timeout を付ける。
- 書き出し：`godot --headless --path sequel --export-release "Web" web/index.html`（テンプレートは 4.4.1 の web_nothreads）。index.wasm は版が同じなら毎回同じ中身。
- ブラウザ：web/ を http で配信し、playwright（swiftshader）で 844×390 を撮る。
