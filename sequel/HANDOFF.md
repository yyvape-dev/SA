## Web の重さの計測（2026-11-07、specs/web_perf.md。直す前の報告）
- 計測の URL：`?perf=1`（console に PERF・PERF_SPIKE・BOOT）、切り分け `?fx2d=0`・`?fxglow=0`・`?glow3d=0`・`?vig=0`。
- 事実：pck の 99％ は可逆の絵（ラナ 32MB・敵の攻撃 10.5MB〈元は非可逆で 2.6 倍に膨張〉）。Pages は gzip のみ（br なし）、pck はほぼ縮まない。2D の層の glow が、エフェクトが無いコマでも毎コマ（fps −約27％）。絵の GPU メモリ 約 500MB。回線を絞ると d1 を使えるまで原因不明の 57 秒。直し方の表は spec の 3。
- 直した（spec の 5）：2D の層は空の間止める（普段 +20〜41％）、敵の攻撃の絵は非可逆 0.95（本体 46.6→39.9MB）、`?perf=1` で画面の隅に fps 等。判定待ち：層の半分の解像度（`?fxhalf=1`）、ラナの Basis（15MB・GPU 38MB・PSNR 30dB）。原因特定：回線が細いと地区 pck の読み取りが 1 コマ数 KB に頭打ち（d1 で 63 秒）→ fetch で丸ごと＋同時取得の案。

## 決まり：地区 pck（2026-11-06）
- 不具合（2026-11-06、ユーザーの PC の Chrome、Windows）：起動直後から背景が仮の箱。事実＝看板の映り込みも無く提灯の筋だけ＝d1.pck 自体を読めていない（手元で d1.pck を 404 にすると同じ画面になる）。手元の Chromium（初回・2回目以降・保存領域を5MBに絞る）では再現しない。対策：pck の置き場所を user://（IndexedDB）から /tmp（メモリ上、残らない）へ、前の版が残した user://*.pck を消す、失敗したら1回やり直す、それでも駄目なら左上に赤い「! <地区> <結果> <HTTPの番号>」を出す（`loading.gd` の error_text）。原因は未確定（その番号で判断する）。続き：ユーザー「赤い文字も出ない」→ 古い版が残っている疑い。本体の index.pck も `?v=<版>` 付きで取りに行く（`export_web.py` が index.html の GODOT_CONFIG に mainPack を足す）。`?diag=1` で左上に版・d1 の状態・glints の数・絵の有無・URL を出す。→ PC の表示は `d1 NG d1 8 200`＝HTTP 200 だが結果 8（BODY_DECOMPRESS_FAILED）。原因＝GitHub Pages が圧縮して送り、ブラウザが解いた後に Godot の HTTPRequest がもう一度解こうとして失敗（手元の http.server は圧縮しないので再現しなかった）。対策＝`accept_gzip = false`（ユーザーの PC で直ったと確認済み）。手元のブラウザ確認は `python3 -I sequel/tools/serve_gzip.py sequel/web`（.pck を gzip で送る＝Pages と同じ）で行う。
- 地区ごとの絵は本体（`web/index.pck`）に入れず、`web/districts/<id>.pck` に分ける。今は d1＝歓楽街（`art/painted/*`・`assets/ground/*`・`glints.json`）。本体 36.6MB → 19.1MB、d1 17.5MB。
- 書き出しは必ず `python3 -I sequel/tools/export_web.py`（godot の --export-release を直接使わない）。版の番号（時刻＋commit）を `build_ver.json`（本体）と `districts/<id>_ver.json`（地区）に同じ値で書き、書き出し設定（"District <id>"）を作り直し、本体と地区 pck を書き出して中身を確かめる。地区を足すときは、この中の `DISTRICTS` に書く。
- 起動：`district.gd` の `ensure(id)` が `districts/<id>.pck?v=<版>` を落とし、`load_resource_pack(..., false)`（本体を上書きしない）。中の版を本体と照らし合わせ、ずれていたらページを 1 回だけ読み直す（`?r=`。2 回目もずれたらそのまま進む）。手元（エディタ・撮影）では res:// の絵をそのまま使う。
- 読み込み中は `loading.gd`（暗転＋右下の小さな回る印、文字なし。いちばん上の層）。読み終えたら 0.3 秒で消える。Web では準備完了の時刻を `window.__sa_ready` に入れる（起動時間を測るため）。
- 地区を出るときは `release_district()`：その地区の絵で作った物を捨て、絵への参照を手放す。事実（`DISTRICT_RELEASE_TEST=1`）：絵のメモリ 92.2MB → 34.5MB。
- `HTTPRequest.download_chunk_size` は 4MB（既定 64KB だと 1コマに 64KB ずつしか受け取らず、遅い端末で数十秒かかった）。`<link rel="preload">` での先読みは二重に落として逆効果だった（使わない）。
- 起動から準備完了まで（iPhone 13 横持ち相当 844×390・DPR3、swiftshader、ゲームの合図で測定）：回線の制限なし 前 2.1〜3.5 秒 → 後 3.9〜4.8 秒、20Mbps 相当 前 35.0〜35.3 秒 → 後 38.7〜39.8 秒（地区 pck を本体の起動後に取りに行く分、約 1.5〜4 秒遅い）。
