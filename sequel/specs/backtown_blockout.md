## 層の構成（手前から）
1. **手前の物**（kind=fg、板、背景を抜く）：足場の柱・吊り下がった灯りが、時々画面を横切る。暗く。ラナから2.5m以内では透ける（今の仕組み）。
2. **歩く帯**：床はコードで作る（今の石畳の素材、暗め）。映り込みは `make_glints.py` で作り直す。何も置かない。
3. **正面の壁**（kind=bld、正面の板）：屋台・テント・店先。扉と屋台は地面の高さに置く（9）。高さ14m前後（見どころは0〜4m、下の「高さの見せ方」）。2画面で4〜6棟。間に柱・路地の隙間（6）。
4. **頭上**（板、背景を抜く）：鉄骨の足場、渡り廊下、垂れ下がる布と電線。壁の少し手前・上に置いて、上を暗く締める。
5. **遠景**（1枚の板、今の `_build_far_plane` の作り方）：積み重なった塔の影と、地平で紫にかすかに光る門。切れない幅を計算する。
   - **見える窓に合わせた書き割りにする（2026-11-08 ユーザー承認）**：カメラ D2 はほぼ水平の望遠なので、遠景の上はほとんど映らない（下の「高さの見せ方」の計算）。巨大な塔や門は実際の縮尺にせず、遠景の板で実際に画面に映る帯（高さの範囲を計算する）の中に、全体の形が収まる大きさで描いた横長の絵にする。発注では、その帯の縦横比のまま頼む（下絵で帯の範囲を色で示す）。上の映らない部分は描かせない。

## 高さの見せ方（2026-11-08 ユーザー承認）
- 事実（計算。チャットが D2 の値から出した概算。Claude Code が正確に計算し直すこと）：D2（高さ 3.2m・見下ろす 6.3°・縦の画角 16.8°）では、画面の上端の視線はわずかに上向き（約2°）。そのため画面に映る高さの上限は、建物の正面（z −6.5、カメラから約22m）で**地面から約4m**、遠景（z −62）でも約6m。比較画像でも、シャッターの上あたりで画面が切れている（事実）。
- **普段の画面の見どころは、地面から0〜4mの帯に集める**（扉・屋台・店先・看板の下段・ビジョン）。それより上は普段は映らない。壁の高さ（目安14m）は、必殺技の寄り・揺れ・カメラの上下で上が切れないための余白で、描き込みは少なくてよい。
- **頭上の層は「垂れ下がる物」で見せる**：渡り廊下・足場そのものは映らないので、そこから4m以下まで垂れ下がる布・提灯や灯り・電線のたるみ・看板で、頭上に何かがあることを見せる。
- **遠景は、建物の隙間（路地の口・建物の間）からだけ見える**。門や塔の書き割りは、その隙間から見える高さ（地面〜約6m）に、形が分かる大きさで置く。
- 高さのある景色は、普段の画面ではなく次で見せる：遠景の書き割り（上の5）、区画の入口や物語の場面の一枚絵の挿絵（`art/concept/backtown_*.png` が候補）。区画に入るときにカメラを上へ振る演出は、あとから足せる（今回は作らない）。

## 人混み（ユーザー：人はいた方がいい。2026-11-07 に方針決定）
- 人混みはこの町の雰囲気そのもの（world_concept）。**絵には描かず、コードで動かす。**
- 置き場所：正面の壁の前の店先の帯（屋台の前〜壁際、歩く帯より奥）。ここを人混みの帯として、下絵の段階で奥行きの幅を取っておく（目安1.5〜2m）。歩く帯には置かない（敵と見分けがつかなくなる）。
- 見た目：敵やラナより暗く・彩度を落として、背景の一部として読ませる。歩く・立ち止まる・屋台の前で向きを変える程度。
- 今回の絵：前作の町の人（今も使っている暗くした絵）を仮に流す。新しい画風の町の人は、画風が決まってから別に発注する（立ち絵数種＋動画AIの短いループ＋色違い。義手・義眼の人も混ぜる＝world_concept）。
- 遠景だけは絵に描いてよい：遠くの渡り廊下や窓の、小さな暗い人影。遠景の発注のときだけ「Do not draw any people」を「only tiny dark silhouettes far away」に替える。
- 予想される失敗：人が多いと重い → 人数と描画の負荷を `?perf=1` で測り、上限を決める。

## 扉・屋台・路地（今回は形と印だけ）
- 扉：幅1.6m・高さ2.6m程度。入ると暗転して部屋へ、の仕組みは今回作らない（スタブ。`doors` のデータと、近づくと出る印まで）。
- 屋台：前の床 2m を空ける。NPC の立ち位置の印だけ置く。
- 路地の入口：壁の隙間の暗い口。ダンジョンの奥・手前の出口と同じ扱いにできる位置。

## 進め方（順番を守る）
1. 下絵を作る（正投影で撮る。区画全体の正面図 `key_front` ＋部品ごと）。
2. ゲームの中で、色の付いた下絵のまま、カメラ D2で撮る。層・高さ・扉の位置を比較画像でチャットに見せる。**ここでユーザーが判定する（塗る前に）。**
3. 判定が通ったら、`tools/make_order.py --base tools/style_base_v2.txt` で発注票を作る（添付1＝その部品の正面の下絵、添付2＝塗った key_front）。key_front は「0. 画風を決める1枚」として最初に頼む。
4. 届いた絵を取り込み、元の絵と同じ大きさで並べて確かめる。明るさは係数で合わせる。

## 判定（2026-11-08 チャット。ユーザーへ提示）
下絵の比較画像（`backtown_img/bt_play_D2.png`・`bt_key_front_window.png`）を見ての判定。全体のバランス（5棟・柱・路地・店先の人混みの帯・扉と屋台の位置）は良い。

### 追加の指摘（先に直す）：壁の絵の解像度の使い方
- 事実：壁の絵 1024×2048 のうち、普段映るのは下の 29%（0〜4m）。そのため細かさが iPhone の画面の 0.82 倍になり、ぼやける。GPU のメモリの7割を映らない所に使っている。
- **壁は「下の帯（地面〜約5.5m、寄り・揺れの余白込み。必殺技の寄りで映る最大の高さを計算して決める）」と「上（それより上）」に分ける。**
  - 下の帯：発注して塗る本命。細かさは画面の 1.0 倍以上を目標に（GPT が出せる大きさに合わせて決める）。
  - 上：暗い、描き込みの少ない絵（全棟で共通の1枚を色違いにする、または下の帯の発注のときに一緒に低い細かさで）。普段は映らない。
- 報告：帯の高さ・絵の大きさ・細かさの倍率・合計 MB / GPU メモリの見込み。

### 判定してほしい点への答え（チャットの推し。ユーザーの了承待ち）
1. 前へ出る箱：**a）出っ張りも壁の絵の中に描かせ、平らにする**。理由：側面の伸びは前に2回起きた失敗。D2 は望遠で見下ろしが 6° だけなので、出っ張りの立体は見た目にほとんど効かない。庇・屋台の台の影は絵の中に描かせる。
2. 手前の足場の柱：**今のままでよい**。ただし塗るときは暗いシルエット寄りにする（手前の物だと分かるように）。ラナに近づくと透ける仕組みは必ずつなぐ。
3. 頭上の飾り：**提灯はやめて、ペンダントライトにする（2026-11-08 ユーザー：ここの提灯は意味が分からない）**。電線やケーブルから吊るした、結晶と真鍮の魔導の灯り（world_concept の「魔法と技術の混ざった照明器具」）。一番低い灯りを 3.0〜3.2m まで下げる。扉（2.6m）より上なので、扉とは重ならない。
4. 遠景の門：**全体の遠景の板ではなく、路地ごとの奥に小さな書き割りの板を置き、門を路地に固定する**。理由（推測）：遠景はカメラが動くとずれる（視差）ので、幅の狭い路地の口と合わせても、カメラが動くと門が口から外れる。路地の奥に固定すれば常に見える。片方の路地は「門へ向かう道」（ダンジョンの入口）にできる。全体の遠景の板はほぼ映らないので、無くして絵を1枚減らす。

- 提灯 → ペンダントライトの置き換え（2026-11-08 ユーザー決定）：下絵の頭上の層（`_build_lanterns` 由来のたるんだ提灯の列を含む）と、頭上のシートの発注の中身を、すべてペンダントライトにする。発注のプロンプトにも「paper lanterns」を書かない（前の発注で和の提灯が昭和に見えた失敗の再発を防ぐ）。
