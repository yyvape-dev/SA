# エフェクト全体の作り直し（2026-11-07〜）

前提：前回の `specs/vfx_recipes.md`（白光り・周辺の赤・色収差・縁の光・粒子の混ぜ撒き）は **ユーザー判断で「とりあえず不採用」**。ゲームのコードは commit 6dc08a5 の前に戻した（文書と比較画像は記録として残した）。

## A. 共通の土台

### A-1. glow（hdr_2d＋背景 Canvas の WorldEnvironment）
**作り**：`scripts/fx2d.gd`。2D のエフェクト専用の SubViewport（`use_hdr_2d = true`、`WorldEnvironment` は `background_mode = Canvas`・`glow` あり・閾値 0.7・加算・トーンマップ Linear、黒地）に描き、その絵を CanvasLayer（layer 1、UI より先に足して UI の下）に**加算**で重ねる。光らせたい色は `fx2d.raw(色)`＝RAW 1.3 倍。UI は別の CanvasLayer なので光らない。画素はウィンドウの実寸で描く（`size_2d_override` で座標だけ 1280×720 基準、解像度は下げない）。

**この形にした理由（事実）**
| 試したこと | 結果（パソコンの描画 opengl3 と Web〈chromium＋swiftshader〉で同じ） |
|---|---|
| 小さな試験プロジェクト：hdr_2d＋背景 Canvas、色 RAW 0.9・1.3・2.0 の四角を「背景の canvas（layer 0）」「3D の板」「UI の CanvasLayer（layer 1）」に置く | 背景の canvas：2.0 ははっきり光る、1.3 は弱く光る、0.9 は光らない。UI の CanvasLayer：どれも光らない。3D の板：2.0 だけわずかに光る（`vfx_overhaul_img/glowtest_desktop_web.webp`。上段＝パソコン、下段＝Web、左＝glow あり） |
| hdr_2d を切る | 背景の canvas も光らなくなる（1 を超える色が 1 に切られる）。→ hdr_2d は必要 |
| SA2 の画面にそのまま当てはめる | SA2 は 3D が画面全体を覆う（建物・路面・遠景）。背景の canvas に置いた 2D は 3D の**後ろ**に隠れる → 使えない |
| 2D 専用の SubViewport（背景 Canvas＋glow、黒地）を 3D の上に加算 | 光る。カメラ（Camera3D）は無くてよい。閾値 0.95 だと RAW 1.3（金色）は光らず 2.0 は光る → エフェクトしか無い層なので閾値を 0.7 に下げた |
| **画面全体（プロジェクト設定）の hdr_2d を有効** | **白い横の帯が出た**（`hdr2d_main_streak.webp`）。画面を読む仕上げ（`vignette.gdshader` の衝撃波の歪み）と組み合わさると出る。hdr_2d を切ると消える。fx2d の層を切っても出る＝原因は画面全体の hdr_2d → **画面全体の hdr_2d は使わず、SubViewport だけ hdr_2d** |
- glow の効き（同じ乱数・同じコマで、層の glow あり／なし。`FXGLOW_OFF=1`）：撃破の場面で明るくなった画素 3.4％、当たり 1.9％、乱れ斬り 2.0％。輪の縁が柔らかくにじむ（`glow_fxlayer_on_off.webp`、左＝あり）。
- Web（ブラウザ）：`?fxtest=1` で層のエフェクトが出る、エラー 0（`web_fxtest.webp`）。`?fxglow=0` で層の glow だけ切る、`?fx2d=0` で層を出さない。
- 3D の glow（ネオン・灯り）は前からのまま（閾値 0.78・SCREEN）。Web でも効く（前回の記録）。

### A-3. 大技の暗転と色収差
- 暗転：技（ラナ3つ・リリィ3つ）と必殺技の始まりに、**背景だけ** 0.15 秒で 40％ の明るさへ（＝60％ 暗く）、技の間そのまま、0.25 秒で戻る（`battle.big_moment`・`bg_dim`）。キャラ・エフェクト・UI は暗くしない。
  - 作り：グローバルなシェーダーの値 `bg_dim`（`project.godot` の `[shader_globals]`）を、建物（proj_paint）・遠景（far_paint）・奥の地面（far_ground）・路面の映り込み（glint）・提灯（lantern）・手前の板と人の流れ（`sprite_bb` の `bg_layer`）が掛ける。路面（StandardMaterial3D）は main が色で掛ける。Web で動く（事実：ブラウザでエラー 0）。
- 色収差：大技の決め（乱れ斬りの最後・地走りの 3 回目・金の渦の最後・必殺技の決め・雷陣の最後・天雷）の一瞬、中心から外へ赤と青をずらし、0.25 秒で引く（`vignette.gdshader` の `chroma`）。

## A-4. iPhone の不具合と対処（2026-11-07、ユーザー報告）
- 報告（事実）：iPhone で、いくつかの攻撃の時に光る正方形・長方形の枠が出る。爆発が見えない。
- 原因（推測。iPhone の実機は確かめられない）：REEBO の4種は、白い 4×4 の画像（`quad.png`）を拡大した板に、自前のシェーダーで形を描く作り。iPhone の Safari でこのシェーダーが動かないと、白い四角がそのまま出て、RAW 1.3 の色で光る。報告の「光る四角」「爆発が見えない」と一致する。パソコンのブラウザ（chromium）では動くので、こちらの確認では出なかった。
- 対処：REEBO の4種を **連番の絵に焼いた**（`tools/bake_reeboo.gd`。1コマ 320px・横 8 列・30fps、元の 1.2 倍、黒地、明るさだけを RGB に入れて色はゲームで掛ける）→ `assets/vfx/reeboo_<名前>.png`・`reeboo.json`。ゲームは絵をめくるだけ（Sprite2D＋加算）で、REEBO のシェーダーを使わない。爆発の灰色の煙は焼かない（加算の層では暗くできず、灰色の光の塊になる）。Kenney の粒も GPUParticles2D をやめ、CPUParticles2D にした（より確実に動く方）。
- 焼き直し：`xvfb-run -a godot --path sequel --rendering-driver opengl3 --fixed-fps 30 -s res://tools/bake_reeboo.gd`
- 途中で分かった事実：焼いた絵を白黒（L8）で保存すると、Web（chromium）で表示されなかった（推測：L8 は色の並べ替え〈swizzle〉で表すが、WebGL2 には無い）→ RGB で保存して表示された（`vfx_overhaul_img/web_baked.webp`）。
- 見た目：焼いた版とシェーダー版は、同じコマでほぼ同じ（`baked_vs_shader.webp`：左＝前、中＝シェーダー版、右＝焼いた版）。粒の出方は毎回同じになる（焼いた時の乱数で固定）。
