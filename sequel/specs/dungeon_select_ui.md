# ダンジョンの選択画面（門→地図→難易度→仲間）— デザインの仕様と Codex への引き継ぎ（2026-11-15）

仕組みは Claude Code が実装済み（branch `claude/skill-tree-implementation-fsvlcl`、commit b478f0a）。**絵と見た目はすべて仮**（コードで描いた図形）。この文書は、見た目を Codex に作ってもらうための仕様。

## 0. ユーザー決定（事実）
- ラナ1人で街から始まる。ダンジョンの門をくぐると地図が広がり、ダンジョンが複数並ぶ（**アラド戦記スタイル**）。
- ダンジョンを選んで入場を選ぶと、仲間の選択画面。1人／リリィ／ランカ／今後の仲間から選んで入場。
- **ハード以上は3人入場可**（ノーマルは2人までと解釈して実装。ユーザーは「良いね」で了承）。
- **デザインが必要な部分はすべて Codex に任せる**（2026-11-15）。

## 1. 体験（何を感じさせるか）
- 最初の10秒：門をくぐる→暗転→**夜の帝都の地図が広がる**。どこへ行けるか、どこが奥かが一目で分かる。
- 1分：ダンジョンを選ぶ→難易度を決める→誰と行くかを選ぶ→入場。迷わず3〜4回押すだけで入れる。
- 繰り返し遊ぶ中：クリアした印・最速の時間・開いた道が増えていくのが地図で見える。

## 2. 今の流れと画面（事実。`scripts/dungeon_hud.gd`）
| 段階（`menu_stage`） | 画面 | 押せる所（`menu_rects()` のキー） |
|---|---|---|
| `"theme"` | 地図（全画面）。門（左下）→T1→T2→T3→T4 の道。開いた所まで金の線、先は暗い点線 | `node0`〜`node3`（各ダンジョン）、`close`（右上の×＝閉じる） |
| `"diff"` | 地図＋右の札（選んだダンジョンの印・難易度3枚・入場の▶） | `node*`、`diff0`〜`diff2`、`go`、`close`（＝地図へ戻る） |
| `"party"` | 中央の札：ラナ（固定）＋仲間4枠（リリィ・ランカ・今後の2枠は錠）、上に人数の印、入場の▶ | `ally0`〜`ally3`、`go`、`close`（＝右の札へ戻る） |

- 描く関数：`_menu()`（地図）・`_dg_panel()`（右の札）・`_party()`／`_face_card()`（仲間）・`_go_btn()`・`_person()`（人の印）・`_theme_glyph()`（テーマの仮の印）・`_lock()`・`_diamond()`・`_clock()`・`_close_x()`。
- 座標は 1280×720 を基準に `u = 画面の高さ/720` 倍。横長の画面（iPhone 844×390＝2.16:1）では左右に余りが出るので、`ox` で中央へ寄せている。**基準の 1280×720 の外（左右の余り）にも地図の地が続くこと**。
- 状態の情報（絵に反映すること）：
  - テーマが開いているか `progress.theme_open(i)`（前のテーマのノーマルをクリアで開く）
  - 難易度が開いているか `progress.diff_open(テーマ, 難易度)`、クリア済み `progress.cleared(…)`、最速 `progress.best[キー]`
  - 仲間が読み込み済みか `main.ally_ready(id)`（読み込み前は薄く＋錠）、選んだ仲間 `hud.pick`、上限 `hud.party_cap()`（ノーマル2・ハード以上3）
  - 押せない物を押すと札が揺れる（`shake_i`：地図 10+i、難易度 0〜2、仲間 20+k、人数 30）

## 3. 守ること（ユーザーの決まり）
- **画面に文字を出さない**（今の日本語フォントに字が足りない。技名・体数の文字は出さない）。**数字は出す**（最速の時間など）。記号・色・絵で伝える。
- 色：**青＝味方・ノーマル、赤＝敵・ハード、金＝物資・決着・決定**。エキスパートは赤＋金。テーマの色は `scripts/dungeon_themes.gd` の `col`（T1 桃・T2 水色・T3 紫・T4 緑）。
- 絵は縮めない・崩さない。処理した絵は元絵と同じ大きさで並べて比べてから入れる。
- タッチできる所は約44〜48px 以上（iPhone 844×390 で）。押したら 100ms 未満で反応（光る・沈む）。
- 足す前に引く。説明の札・帯を足して直さない。

- 画像生成を使うなら、使う絵だけを頼む（使わない案を頼んで上限を無駄にしない）。

## 5. 変えないこと（壊すと困る）
- 流れの関数と戻り値：`open_menu()`・`choose_theme(i) -> bool`（錠なら false）・`choose(i) -> bool`・`toggle_ally(k)`・`go()`・`menu_back()`・`party_cap()`。自動テスト（`scripts/bot.gd`）が `menu_stage == "theme"`・`choose_theme`・`choose` を使う。
- タップの判定は `menu_rects()` の矩形。絵の位置を動かしたら矩形も合わせる。
- `main.gd` のパーティ（`set_party`・`bench`・`party_flow()`）。
- キー操作：地図 A/D・W/S・1〜4・J、仲間 1〜4・J、K で戻る。

## 6. 確かめ方
- 環境の準備・撮影・書き出し・push の手順は `sequel/HANDOFF.md` と Skill `sa2-godot-check`（Godot 4.7.2）。
- 撮影：`cd sequel && rm -rf captures; TOWN=back CAPTURE_MENU=1 UNLOCK_ALL=1 LIBGL_ALWAYS_SOFTWARE=1 timeout 500 xvfb-run -a -s '-screen 0 1280x720x24' godot --path . --rendering-driver opengl3 --windowed --resolution 1280x720 --fixed-fps 60` → `captures/menu_0_town`〜`menu_5_dungeon.png`。`UNLOCK_ALL` を外すと鍵のある地図。
- 自動テスト：`DUNGEON_TEST=1 timeout 300 godot --headless --path . --fixed-fps 60`（鍵3つ「正しい」、run がクリア）。
- Web：`WEB_OUT=../previews/sa2-dungeon python3 -I sequel/tools/export_web.py` → `python3 -I sequel/tools/serve_gzip.py previews/sa2-dungeon` を chromium 844×390 で（`?town=back&at=gate&unlock=1`、門へは D で右へ→W）。
- 見せる前に（Skill `game-experience-review`）：844×390 で撮る／お手本と並べて差を表に／5問（何の画面か・何をすればいいか・押すと何が起きたか・なぜか・次は何か）に1行ずつ答える。
