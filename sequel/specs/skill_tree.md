## 1. 数字（たたき台。チャットの提案、ユーザーは削除・修正なし。遊んでから調整）
- SP：レベルが1つ上がるごとに **+1**（3人それぞれに +1。SP はキャラごとに別）。各難易度（normal・hard）の初回クリアで **+2**（3人それぞれ）。
- 技レベル：1〜5。最初の3技と必殺技は Lv1 で持っている（SP 0）。Lv を1つ上げるのに SP 1。
  - 威力：Lv1 から1つごとに +10％（`k` に掛ける。Lv5 で 1.4 倍）。
  - 待ち（cd）：Lv3 で −10％、Lv5 で −20％。必殺技はゲージの必要量（ULT_COST）を同じ割合で下げる。
- 派生：技レベル **3** で開く。2〜3個から **1つ**選ぶ（SP は使わない）。選ばない＝元の技のまま。
- 新しい技の解放：表に `need_lv`（キャラのレベル）と `need`（前の技の id と技レベル）を書く。取るのに SP 1。今は新しい技が無いので、行は作らずに仕組みだけ用意する。
- 前のセーブからの移行：SP ＝（今のレベル −1）＋ 2 ×（clears が1以上の難易度の数）。技レベルは全部1、派生はなし。

## 3. 実装の型
- 表は1か所：`scripts/skill_tree.gd`（新規）。キャラ → 技 id → `{name, max_lv, need_lv, need, derivs: {派生id: {name, patch}}}`。
- 派生は**元の技の辞書への差分（patch）**で書く。技ごとの if を処理に足さない。`skills.gd`・`lily_skills.gd`・`ranka_skills.gd` の `table()` の結果に、技レベル（k・cd の倍率）と派生の patch を掛けた辞書を返す関数を1つ作り、player.gd・ally.gd・ranka_ally.gd はそれを読む。
- patch で表せない動き（歩き渦・連鎖・往復・結界のように、処理の新しい項目が要るもの）は、`battle._attack_from` の spec か技の辞書に**汎用の項目**を足して読む（例 `move_ok`・`chain_n`・`return_trip`・`linger`）。項目と意味はこのファイルの末尾に追記する。
- セーブ：`progress.gd` に `sp`（キャラ → 数）、`skill_lv`（キャラ → 技 id → Lv）、`deriv`（キャラ → 技 id → 派生 id）、`first_clear_paid`（難易度 → bool）を足す。前のセーブは 1. の移行で埋める。
- SP を足す所：`progress.add_exp` でレベルが上がった数だけ、`dungeon.gd` のクリア処理（`pr.clears[key]` を増やす所）で初回なら +2。

- 作り：`dungeon_hud.gd` の `open_slots` と同じ作り（暗い地・×・外・K で閉じて保存）。
  - 左：キャラのタブ（ラナ・リリィ・ランカ）。選んでいるタブは金の縁。
  - 右上：そのキャラの残り SP。
  - 各行：技のアイコン（今のコードの図形）＋技レベルの丸5つ（埋まった数＝Lv）＋押すと Lv+1。右へ線を引いて派生のノード2〜3個（Lv3 未満は薄く）。選んだ派生は金の縁。

  - 必殺技の行は一番下。
- 文字：UI の文字は使ってよい（`skill_ui.md` と同じ）。日本語フォントが入っていなければ、技名の代わりにアイコンと数字で足りるようにする。

## 5. 確認（撮って並べる）
- `CAPTURE_FX=1 FX_ONLY=tree` を足す：ツリー画面（3人のタブそれぞれ）と、派生ごとの「予兆・当たり・余韻」の3枚 → `captures/ui_tree_<char>.png`、`captures/fx_deriv_<char>_<skill>_<deriv>_<1|2|3>.png`。元の技と並べた比較画像にしてユーザーに見せる。
- 数字：技レベル1と5、派生ありなしで、当たった数・ダメージを `LSKILL_LOG=1` 相当で出す。
- 自動の4周（`--fixed-fps 60`）：派生をランダムに付けた状態で全部クリア・抜け道なし。
- セーブの移行：前のセーブ（skills_owned だけのもの）を読んで SP が 1. の式どおりになること。

## 7. 処理に足した汎用の項目（2026-11-14、実装 Claude Code）
派生は `scripts/skill_tree.gd` の patch（差分）で書く。patch の操作（set・mul・thin・dense・lerp・fork・append）は skill_tree.gd の先頭に説明。処理側で読む項目：
| 項目 | どこで読む | 意味 |
|---|---|---|
| `z_slope` | battle._attack_from | 帯・前方の当たりを斜めに（1m 進むごとに奥行きが何 m ずれるか）。三叉・散弾 |
| `seek_n`・`seek_r` | battle._attack_from | 半径 seek_r の中の近い敵 seek_n 体だけに当てる。追雷 |
| `pull: "out"` | battle._attack_from | 寄せの逆。外へ pull_m 押す。反転 |
| `linger: {n, gap, k, band}` | battle._attack_from・_update_lingers | 当たりがその場に残り、gap 秒ごとに n 回当たる（威力は k 倍、床の輪を出す）。結界 |
| `origin` | battle._attack_from | 当たりの中心を固定（linger が使う） |
| `band_fx`・`burst_fx` | battle._deriv_fx | 帯の気の筋／円の炸裂（光の爆ぜ・床の輪・柱・砂煙）の見た目。値は色の帯の名前 |
| `rev` | battle.player_skill（vortex） | 渦の回る向きを逆に・外へ広がる輪 |
| `move_ok`・`move_spd` | player.gd（skill の状態） | 使いながら動ける（走りの move_spd 倍）。歩き渦 |
| `chain_n`・`chain_r` | ally.gd（_chain_next） | 技の終わりに chain_r m 以内のまだ当てていない敵へ跳び、同じ技をもう一度（合計 chain_n 体）。連鎖 |
| `dash_back`・`back` | ally.gd（_skill_step・rush） | dash_back の間に走り出した所へ戻り、戻りの帯にも当てる。往復 |
| `cost_mul`・`k_hit`・`k_end`・`k_step` | 各キャラの ult_cost()・必殺技の処理 | 必殺技の技レベル（ゲージの必要量・威力） |
