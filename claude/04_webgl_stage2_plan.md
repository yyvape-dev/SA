# WebGL 移行・段階2（アクション戦闘）の計画案　2026-10-31

## 追記 21:40　キャラ・コマを増やすなら（ユーザーの問い）
* 問い：キャラやコマを増やすと決めたとき、スマホの実機で軽いのは？ GL なら全面移行が合理的。
* 答え：**キャラの数が増える → GL（PixiJS）が軽い。コマが増える → 圧縮テクスチャを使える GL が有利。** → 全面移行（2b）が合理的。2a の橋渡しは作らず、fx_gl のシェーダーを PixiJS の Mesh＋Shader に載せ替えて持っていく（GLSL はほぼそのまま使える）。
* 事実：Canvas 2D は1枚描くごとに1回の命令。合成の切り替え（lighter／source-over）・save/restore・filter・shadowBlur が重い（今の battle は1コマに何十回も切り替えている）。PixiJS は同じ絵の束（アトラス）のスプライトをまとめて1回で描く（バッチ）。
* 事実：コマの絵は、どちらも展開後は 1画素4バイトでメモリを使う。Canvas は圧縮できない。GL は GPU の圧縮形式（KTX2/Basis など）で数分の1にできる。iOS Safari には Canvas のメモリの上限があり、超えると描けなくなる。
* 仮説（実機で測るまで）：今の量（敵数体＋仲間）では差は小さい。差が出るのは敵が十数体以上か、コマの絵が今の数倍になってから。
* ユーザー決定待ち：2b（PixiJS へ全面移行）へ直行するか。

## 結論（提案）
段階2は「PixiJS へ全面の作り直し」ではなく、まず **2a：アクション戦闘の Canvas の上に WebGL のエフェクトの層（fx_gl.js）を重ねる**。
PixiJS への全面移行（2b）は、2a の後に実機で重さ・質を測って、足りないときだけ行う。→ ユーザーの判断待ち。

## 事実（コードを数えた結果）
* アクション戦闘は `index.html`（ルート）＋ `battle/*.js` 10本・約2,300行。classic script（トップレベルの var を共有）。描画は `battle/core.js` の1枚の Canvas 2D（`ctx`）。
* 描画の呼び出しは draw.js・fx.js・fx2.js・ally.js に集中（`ctx.` が draw 126・fx2 101・fx 68 行）。エフェクトは `drawFx()` から `FX2[type]` へ振り分け。
* fx_gl.js は ES モジュール（terrain 側）。battle は classic script なので、読み込みは `import('../terrain/fx_gl.js?v=…')`（動的 import は classic script からも使える）。

## 2a の段取り（目安：2〜3回の作業）
1. `battle/glfx.js`（薄い橋渡し）：起動時に `createGL(#stage)` を作り、戦闘の Canvas と同じ大きさ・同じカメラ（camX/camY・揺れ）を毎コマ渡す。使えない／描画がリセットされたら今の Canvas の弧に戻す（段階1と同じ）。
2. 置き換えるのは弧だけ：`drawVArc`（ラナ・仲間の斬撃）・`drawVLance`（突き）・敵の攻撃の弧。火花・光・リング・煙は Canvas のまま。
3. 素材：発注票の5件が届いたら、帯1＝剣の基本、帯2＝突き・速い太刀、帯3＝斧・重い一撃、ノイズ1＝侵食のむら、ノイズ2＝流れるすじ。
4. 確認：ヘッドレスでコマ送り（今の Canvas 版と並べる）＋ 実機のスマホで重さ（fps）。

## 2b（PixiJS へ全面移行）をすぐやらない理由（仮説を含む）
* 質の差を生むのはシェーダーと素材（侵食・色の帯・流れ）で、絵の並べ方（スプライト描画）ではない（調査の要約より）。2a で質の大半は取れる見込み。【仮説】
* 2,300行の描画を書き直す量に比べ、画面に出る差が小さい。PixiJS の読み込みも数百KB 増える。
* 2b が必要になる合図：敵が多い場面でスマホが 50fps を切る／Canvas と WebGL の重ね順（キャラの後ろにも光を置きたい等）で困る。

## 調査の答え合わせで直すこと（fx_gl.js、素材が届いたとき一緒に）
* 一回きりの斬撃は形の絵を **繰り返さない（CLAMP）**。今は REPEAT＋流し（`uRep 1.3`・`uPan`）。流すのはノイズだけにする。【出典：realtimevfx のトレイルの解説（検索の抜粋）】
* 侵食に **向き** を付ける（消える順番に u の傾きを掛け、尾から先へ欠ける）。【出典：realtimevfx「Battlerite Erosion」返信（抜粋）】
* 白黒の幅を目いっぱい使う（素材の発注に反映済み）。【出典：VFX Apprentice の講座紹介（抜粋）】
* 暗い下地・2つの絵の掛け合わせは、今の試作と一致。
