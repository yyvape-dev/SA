# ゲームシナリオ制作・改稿の教科書
更新：2026-11-02／対象：SAを執筆する人、Claude Code、Claude、Codexなど。

## この教科書の使い方
物語の魅力を、設定の量や台詞の美しさだけで判断しない。「誰が何を望み、何を選び、その結果が何に残ったか」を、プレイヤーが体験できるようにする。

これは成功を保証する法則集ではない。王道・一本道・温かい仲間関係というSAの良さを伸ばすための診断道具である。三幕構成、成長、対立、悲劇、分岐を一律に強制しない。ユーザーの意図と採用済み設定を優先する。

## 読む順番
1. [原則編](01_principles.md)：物語・人物・場面・文章・ゲーム固有の設計。
2. [実践編](02_workbook.md)：弱い例と改善例、設計テンプレート、レビュー・検証手順。
3. [SAへの適用メモ](03_sa_revision_map.md)：現状の長所と問題、改稿の優先順位。提案は未採用。
4. [出典と調査ノート](04_sources.md)：一次資料、確認範囲、資料の主張と本教科書の編集判断。

## 最初に覚える10項目
- 主人公の肩書きより、その人が今ほしいものを示す。
- 出来事を並べるだけでなく、前の選択が次の問題を生むようにつなぐ。
- 人物の魅力は、能力・生活・矛盾・他人への接し方・選択の組み合わせで作る。
- 告白、理解、行動の変化、他人からの信頼回復は、別の段階である。
- 本人の気持ちは本物でも、自己分析が正しいとは限らない。
- 悲惨さや死者の数ではなく、具体的に大切だったものと変化で重みを作る。
- 伏線は、後で思い返せる情報として先に渡す。
- 選択では、意図と予測できるリスクを伝え、後で反応を返す。
- 会話・戦闘・運営・地図の変化が、同じ出来事を語るようにする。
- 読んだ人の反応で検証する。チェック項目の達成数を品質と取り違えない。

## AI執筆者への引き継ぎ
- 原則編と適用メモを読んでから改稿する。現状確認は計画書だけでなく実装本文と呼出順で行う。
- 「現在の実装」「ユーザー確定事項」「この教科書の提案」を混ぜない。例文はすべて学習用であり、採用済み台詞ではない。
- 改稿前に、残す魅力、解決する問題、変える因果、後で回収する箇所を記録する。
- 全員を賢く優しい相談役にしない。主人公以外にも目的・意見・生活を持たせる。
- 深みを出すためだけに、死、虐待、裏切り、救えない人を追加しない。
- 任意会話の既読を本筋の前提にしない。プレイヤーと登場人物が何を知るかを区別する。
- 戦闘の敗北、イベント再開、絆会話の時期、章冒頭と週イベントの重複まで確認する。
- 本教科書の追加時点では、ゲーム本文・人物設定・戦闘ルールを変更していない。

## 文書の位置づけ
出典付きの短い要約を土台にした、SA用の編集・設計資料。学術的な普遍法則の証明や、商業作品の優劣ランキングではない。既存作品のネタバレによる説明は避け、独自の教材例で説明する。
